# ImageManager2 — 数据库设计文档

## 1. 概述

### 1.1 数据库选型
- **数据库**：SQLite 3.x
- **访问方式**：Dapper (Micro-ORM) + Microsoft.Data.Sqlite
- **存储位置**：`%LocalAppData%/ImageManager/data.db`
- **连接模式**：WAL (Write-Ahead Logging) + Foreign Keys ON
- **连接管理**：每个 Repository 方法创建独立连接 (`new SqliteConnection` + `using`)

### 1.2 设计原则
- 所有表使用 `IF NOT EXISTS` 创建，确保幂等初始化
- 主键采用自增 INTEGER PRIMARY KEY
- 外键启用 CASCADE 删除
- 所有查询使用 FolderId 索引而非 LIKE 路径匹配
- 路径字段使用 NOCASE 排序规则

## 3. 表结构定义

### 3.1 ImageMeta — 图片元数据

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| Id | INTEGER | PRIMARY KEY AUTOINCREMENT | 主键 |
| FilePath | TEXT | NOT NULL, UNIQUE | 文件完整路径 |
| FileHash | TEXT | | MD5 哈希 (小写十六进制) |
| PerceptualHash | TEXT | | 组合感知哈希 `aHash\|dHash\|wHash\|histogram` |
| Width | INTEGER | | 图片宽度 (像素) |
| Height | INTEGER | | 图片高度 (像素) |
| FileSize | INTEGER | | 文件大小 (字节) |
| LastWriteTicks | INTEGER | | 文件最后修改时间 (DateTime.Ticks) |
| FolderId | INTEGER | FOREIGN KEY → Folder(Id) | 所属文件夹 (可空) |
| CreatedAt | TEXT | | 记录创建时间 (UTC) |
| UpdatedAt | TEXT | | 记录更新时间 (UTC) |

**索引**：
- `IDX_ImageMeta_FilePath` ON FilePath
- `IDX_ImageMeta_FileHash` ON FileHash
- `IDX_ImageMeta_FolderId` ON FolderId

**DDL**：
```sql
CREATE TABLE IF NOT EXISTS ImageMeta (
    Id INTEGER PRIMARY KEY AUTOINCREMENT,
    FilePath TEXT NOT NULL UNIQUE,
    FileHash TEXT,
    PerceptualHash TEXT,
    Width INTEGER,
    Height INTEGER,
    FileSize INTEGER,
    LastWriteTicks INTEGER,
    FolderId INTEGER,
    CreatedAt TEXT,
    UpdatedAt TEXT,
    FOREIGN KEY (FolderId) REFERENCES Folder(Id) ON DELETE SET NULL
);
```

### 3.2 Tag — 标签

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| Id | INTEGER | PRIMARY KEY AUTOINCREMENT | 主键 |
| Name | TEXT | NOT NULL, UNIQUE | 标签名 |

**索引**：
- 唯一约束自带 UNIQUE(Name) 索引

**DDL**：
```sql
CREATE TABLE IF NOT EXISTS Tag (
    Id INTEGER PRIMARY KEY AUTOINCREMENT,
    Name TEXT NOT NULL UNIQUE
);
```

### 3.3 ImageTag — 图片标签关联

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| ImageMetaId | INTEGER | NOT NULL, FK → ImageMeta(Id) ON DELETE CASCADE | 图片 ID |
| TagId | INTEGER | NOT NULL, FK → Tag(Id) ON DELETE CASCADE | 标签 ID |

**索引**：
- `IDX_ImageTag_ImageMetaId` ON ImageMetaId
- `IDX_ImageTag_TagId` ON TagId

**DDL**：
```sql
CREATE TABLE IF NOT EXISTS ImageTag (
    ImageMetaId INTEGER NOT NULL,
    TagId INTEGER NOT NULL,
    PRIMARY KEY (ImageMetaId, TagId),
    FOREIGN KEY (ImageMetaId) REFERENCES ImageMeta(Id) ON DELETE CASCADE,
    FOREIGN KEY (TagId) REFERENCES Tag(Id) ON DELETE CASCADE
);
```

### 3.4 Folder — 文件夹

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| Id | INTEGER | PRIMARY KEY AUTOINCREMENT | 主键 |
| Path | TEXT | NOT NULL, UNIQUE | 文件夹路径 |
| Alias | TEXT | | 用户自定义别名 |
| SortOrder | INTEGER | | 排序位置 |
| LastPageIndex | INTEGER | | 上次浏览的页码 |

**DDL**：
```sql
CREATE TABLE IF NOT EXISTS Folder (
    Id INTEGER PRIMARY KEY AUTOINCREMENT,
    Path TEXT NOT NULL UNIQUE,
    Alias TEXT,
    SortOrder INTEGER,
    LastPageIndex INTEGER
);
```

### 3.5 FavoriteTag — 收藏标签

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| Id | INTEGER | PRIMARY KEY AUTOINCREMENT | 主键 |
| Name | TEXT | NOT NULL, UNIQUE | 收藏的标签名 |

**DDL**：
```sql
CREATE TABLE IF NOT EXISTS FavoriteTag (
    Id INTEGER PRIMARY KEY AUTOINCREMENT,
    Name TEXT NOT NULL UNIQUE

```

### 3.6 AppSetting — 应用设置

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| Key | TEXT | PRIMARY KEY | 设置项名称 (对应 AppSettings 属性名) |
| Value | TEXT | | 序列化后的设置值 |

**DDL**：
```sql
CREATE TABLE IF NOT EXISTS AppSetting (
    Key TEXT PRIMARY KEY,
    Value TEXT
);
```

**键值编码规则**：

| 类型 | 编码格式 | 示例 |
|------|----------|------|
| bool | "true"/"false" | `true` |
| int | 字符串 | `512` |
| double | InvariantCulture | `0.25` |
| string | 原值 | `Dark` |
| List\<string\> | `\|` 分隔 | `角色\|场景\|武器` |
| Dictionary\<string,string\> | `\|\|` 分隔, `=` 连接 | `壁纸=bg.jpg\|\|头像=avatar.png` |

## 4. 数据库迁移

### 4.1 版本迁移记录

| 版本 | 变更 | SQL |
|------|------|-----|
| v1.0 | 初始创建 | 6 张表 CREATE TABLE IF NOT EXISTS |
| v1.1 | 添加 FolderId | `ALTER TABLE ImageMeta ADD COLUMN FolderId INTEGER` |
| v2.0 (未来) | 预留 ONNX 特征向量 | `ALTER TABLE ImageMeta ADD COLUMN FeatureVector BLOB` (规划中) |

### 4.2 迁移策略
- 使用 try/catch 包裹 DDL，忽略 "duplicate column" 错误
- 不执行破坏性操作 (DROP TABLE / DROP COLUMN)
- HashVersion 字段用于检测是否需要触发全量哈希重算

## 5. 查询模式

### 5.1 高频查询

| 查询 | 频率 | SQL 模式 |
|------|------|----------|
| 按文件夹 ID 查图片 | 极高 | `SELECT * FROM ImageMeta WHERE FolderId = @Id` |
| 按文件路径查图片 | 高 | `SELECT * FROM ImageMeta WHERE FilePath = @Path` |
| Upsert 图片元数据 | 高 | 先 `SELECT Id FROM ImageMeta WHERE FilePath = @Path`，有则 UPDATE，无则 INSERT |
| 查图片的标签 | 高 | `SELECT t.Id, t.Name FROM Tag t JOIN ImageTag it ... WHERE it.ImageMetaId = @Id` |
| 设置图片标签 | 中 | 事务内 DELETE 旧标签 + INSERT OR IGNORE 新标签 |
| 标签分组计数 | 中 | `SELECT t.Name, COUNT(*) FROM Tag t JOIN ImageTag it ... GROUP BY t.Name` |
| 标签组合搜索 | 中 | JOIN + GROUP BY + HAVING COUNT |
| 共现标签 | 中 | `SELECT t.Name, COUNT(*) FROM ImageTag it JOIN Tag t ... WHERE im.FilePath IN @Paths GROUP BY t.Name ORDER BY COUNT(*) DESC` |

### 5.2 批量标签加载策略

ImageMetaRepository 采用 **批量标签加载** 而非逐条 N+1 查询：

```
GetByFolderIdAsync(folderId):
  1. SELECT * FROM ImageMeta WHERE FolderId = @Id         → 一次获取所有图片
  2. SELECT it.ImageMetaId, t.Id, t.Name
     FROM ImageTag it JOIN Tag t ON it.TagId = t.Id
     WHERE it.ImageMetaId IN (步骤1的Id列表)               → 一次获取所有标签
  3. 在内存中构建 Dictionary<long, List<TagCount>>
  4. 循环赋值到每个 ImageMeta.Tags
```

总计 2 次 SQL 查询，而非 1 + N 次。

## 6. 性能优化

### 6.1 连接管理
```sql
-- 每次打开连接时执行
PRAGMA journal_mode=WAL;     -- 写前日志，允许并发读
PRAGMA foreign_keys=ON;      -- 启用外键约束
```

### 6.2 批量操作
- `BulkUpsertAsync`：先 `SELECT FilePath FROM ImageMeta WHERE FilePath IN @Paths` 获取已存在路径集合，然后在单个事务中批量 INSERT + UPDATE
- `SetTagsAsync`：DELETE + 批量 INSERT OR IGNORE 在单个事务内完成

### 6.3 查询优化
- 所有标签相关查询通过 `ImageTag` 连接表，利用复合主键索引
- 文件夹级查询优先使用 `FolderId` 索引而非 `FilePath LIKE`（兼容旧路径查询仅在 `GetByFolderAsync` 中保留）
- 感知哈希查询仅 SELECT FilePath + PerceptualHash 两列（轻量查询）

## 7. 数据备份与恢复

### 7.1 备份
- SQLite 单文件架构，复制 `data.db` 即可完成备份
- WAL 模式下需同时备份 `data.db-wal` 和 `data.db-shm`

### 7.2 恢复
- 将备份的 `data.db` 复制回 `%LocalAppData%/ImageManager/` 目录
- 删除残留的 `-wal` 和 `-shm` 文件
- 重新启动应用即可

### 7.3 数据完整性
- 外键约束 ON DELETE CASCADE：删除图片时自动清理标签关联
- 标签重命名：更新 Tag 和 FavoriteTag 表
- 标签合并：先更新 ImageTag 关联，再删除旧标签，异常时事务回滚

# ImageManager2 — 部署运维手册

## 1. 环境要求

### 1.1 运行环境

| 组件 | 最低要求 | 推荐配置 |
|------|----------|----------|
| 操作系统 | Windows 10 (1903+) | Windows 11 |
| .NET Runtime | .NET 8.0 Desktop Runtime | .NET 8.0.x 最新补丁 |
| 内存 | 4 GB | 8 GB+ |
| 磁盘空间 | 200 MB (应用) + 缓存空间 (用户可配) | SSD 推荐 |
| 显卡 | DirectX 11 兼容 | GPU 加速渲染 |

### 1.2 开发环境

| 组件 | 版本/工具 |
|------|-----------|
| .NET SDK | 8.0.x |
| IDE | Visual Studio 2022 / JetBrains Rider / VS Code + C# Dev Kit |
| 构建工具 | dotnet CLI (`dotnet build`, `dotnet publish`) |
| 包管理 | NuGet (Microsoft.Extensions, Avalonia, SkiaSharp, Dapper, SQLite) |

## 2. 构建与发布

### 2.1 获取源码

```bash
git clone <repository-url>
cd ImageManager2
```

### 2.2 还原依赖

```bash
dotnet restore ImageManager2.sln
```

### 2.3 编译

```bash
# Debug 模式
dotnet build ImageManager2.sln -c Debug

# Release 模式
dotnet build ImageManager2.sln -c Release
```

### 2.4 运行（开发模式）

```bash
dotnet run --project src/ImageManager.App/ImageManager.App.csproj
```

### 2.5 发布

```bash
# 发布为独立应用 (自包含 .NET Runtime)
dotnet publish src/ImageManager.App/ImageManager.App.csproj `
    -c Release `
    -r win-x64 `
    --self-contained true `
    -p:PublishSingleFile=false `
    -o ./publish/win-x64

# 发布为单文件应用
dotnet publish src/ImageManager.App/ImageManager.App.csproj `
    -c Release `
    -r win-x64 `
    --self-contained true `
    -p:PublishSingleFile=true `
    -p:IncludeNativeLibrariesForSelfExtract=true `
    -o ./publish/win-x64-single
```

### 2.6 发布输出

```

├── ImageManager.App.exe       # 主程序
```

## 3. 安装部署

### 3.1 便携版部署（推荐）

1. 将 `publish/win-x64/` 文件夹复制到目标机器任意位置
2. 双击 `ImageManager.App.exe` 启动
3. 首次运行自动创建：
   - `%LocalAppData%/ImageManager/data.db` — SQLite 数据库
   - `%LocalAppData%/ImageManager/data.db-wal` — WAL 日志
   - `%LocalAppData%/ImageManager/data.db-shm` — 共享内存
4. 首次运行自动创建默认缓存目录 `C:\ImageManagerCache`

### 3.2 数据目录结构

```
%LocalAppData%/ImageManager/
├── data.db                    # 主数据库
├── data.db-wal                # WAL 日志 (运行时存在)
└── data.db-shm                # WAL 共享内存 (运行时存在)

C:\ImageManagerCache\          # 默认磁盘缓存路径 (可配置)
├── w160/
│   ├── a1b2c3d4....jpg
│   └── ...
├── w200/
├── w295/
├── ...
└── w640/
```

### 3.3 旧版升级

1. 备份旧版数据库：复制 `%LocalAppData%/ImageManager/data.db` 到安全位置
2. 部署新版本文件
3. 如需从 WPF 旧版 JSON 迁移：
   - 打开应用 → 设置 → 数据迁移
   - 选择旧版 `image_data.json` 文件
   - 等待迁移完成，查看统计摘要

### 3.4 卸载

1. 关闭应用
2. 删除应用目录
3. 删除数据目录：`%LocalAppData%/ImageManager/`
4. 删除缓存目录：`C:\ImageManagerCache` (或自定义路径)
5. 无注册表项，无系统服务

## 4. 配置说明

### 4.1 配置存储

所有配置项存储在 SQLite `AppSetting` 表中，无配置文件。通过应用内设置窗口修改。

### 4.2 关键配置项

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| ThemeVariant | "Dark" | 主题 ("Dark"/"Light") |
| WaterfallMode | "None" | 瀑布流模式 ("None"/"Vertical"/"Horizontal") |
| GridZoomLevel | 1 | 网格模式缩放级别 |
| VerticalZoomLevel | 1 | 垂直瀑布流缩放级别 |
| HorizontalZoomLevel | 1 | 水平瀑布流缩放级别 |
| ThumbnailCacheMaxMB | 512 | 内存缓存上限 (MB) |
| DiskCacheDirectory | `C:\ImageManagerCache` | 磁盘缓存路径 |
| ShowThumbnailFileName | true | 显示文件名 |
| ShowThumbnailTags | true | 显示标签摘要 |
| ShowThumbnailOrientation | true | 显示方向标识 |
| ThumbnailCornerRadius | 0 | 缩略图圆角半径 |
| ThumbnailAspectRatio | 1.0 | 缩略图宽高比 |
| MaxTagSuggestionCount | 30 | 标签建议最大数量 |
| HashVersion | "1" | 哈希算法版本 |

### 4.3 配置修改方式

1. **UI 方式**：通过菜单栏 → 设置 → 对应设置窗口 → 保存
2. **数据库方式**（高级）：直接编辑 `data.db` 的 `AppSetting` 表（修改前关闭应用）
3. **重置配置**：删除 `data.db` 文件，启动应用自动重建

## 5. 日常运维

### 5.1 缓存管理

**内存缓存**：
- 上限通过 `ThumbnailCacheMaxMB` 配置（64 ~ 4096 MB）
- LRU 自动淘汰，无需手动管理
- 在 "设置 → 内存与缓存" 中查看当前使用量

**磁盘缓存**：
- 缩略图按解码宽度分目录存储
- 删除文件夹或图片时自动清理对应磁盘缓存
- 可手动删除整个缓存目录（下次浏览时重建）
- 在 "设置 → 内存与缓存" 中查看磁盘使用量

### 5.2 数据库维护

- SQLite 自动管理 WAL 文件，正常关闭应用时 WAL 自动合并
- 如需压缩数据库：关闭应用 → 使用 SQLite CLI 执行 `VACUUM`
- 备份策略：定期复制 `data.db` 文件即可
- 数据库文件增长预估：每 10,000 张图片约 10-30 MB

### 5.3 性能优化建议

| 场景 | 建议 |
|------|------|
| 图片库 > 50,000 张 | 拆分为多个文件夹，每个文件夹 ≤ 20,000 张 |
| 缩略图加载缓慢 | 增大 `ThumbnailCacheMaxMB` (如 2048 MB) |
| 磁盘缓存过大 | 手动删除缓存目录，或在设置中更改缓存路径 |
| 哈希计算慢 | 确保有足够 CPU 核心，应用会自动并行计算 |
| 内存占用过高 | 减小 `ThumbnailCacheMaxMB`，减少同时打开的页面 |

## 6. 故障排查

### 6.1 常见问题

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 应用无法启动 | .NET 8 Runtime 未安装 | 安装 .NET 8.0 Desktop Runtime |
| 缩略图不显示 | SkiaSharp 解码失败 | 检查图片格式是否支持，查看崩溃日志 |
| 图片不自动刷新 | FileSystemWatcher 未覆盖 | 手动切换文件夹触发同步 |
| 搜索无结果 | 搜索语法错误 | 查看帮助窗口确认语法 |
| 标签重命名失败 | 目标名称已存在 | 选择合并或使用不同的名称 |
| 内存占用过高 | 缓存未限制 | 在设置中降低内存缓存上限 |
| 数据库损坏 | 非正常关闭 | 删除 `-wal` 和 `-shm` 文件，重启应用 |

### 6.2 日志文件

- **崩溃日志位置**：`%UserProfile%/Desktop/ImageManager_crash.log`
- **日志内容**：未处理异常的完整堆栈跟踪
- **日志格式**：纯文本，包含时间戳和异常信息

### 6.3 诊断步骤

1. 检查崩溃日志：`桌面/ImageManager_crash.log`
2. 确认 .NET Runtime 版本：`dotnet --info`
3. 验证数据库完整性：使用 SQLite 工具打开 `data.db` 执行 `PRAGMA integrity_check`
4. 检查磁盘空间：缓存目录和数据库目录是否有足够空间
5. 备份并重置：备份 `data.db` → 删除 → 重启应用测试是否清洁启动
6. 清理缓存：删除 `C:\ImageManagerCache` 下所有文件

## 7. 安全注意事项

- 数据库文件包含图片路径和标签信息，建议本地使用，不要上传到公开网络
- 在线搜图功能会向第三方服务器上传图片文件，请注意隐私
- 应用无网络访问权限要求（在线搜图通过系统浏览器完成）
- 应用无管理员权限要求
- 不收集、不传输任何使用数据

## 8. 版本升级

### 8.1 升级步骤

1. 关闭正在运行的 ImageManager2
2. 备份 `%LocalAppData%/ImageManager/data.db`
3. 替换应用文件为新版本
4. 启动新版本，检查功能是否正常
5. 如有 HashVersion 变更，应用会自动触发全量哈希重算

### 8.2 回滚步骤

1. 关闭新版本
2. 恢复旧版本应用文件
3. 恢复备份的 `data.db`
4. 删除残留 WAL 文件 (`data.db-wal`, `data.db-shm`)
5. 启动旧版本

### 9.2 数据库表结构快速参考

```sql
-- 查询所有含特定标签的图片
SELECT im.FilePath FROM ImageMeta im
JOIN ImageTag it ON im.Id = it.ImageMetaId
JOIN Tag t ON it.TagId = t.Id
WHERE t.Name = '角色';

-- 查询标签使用排行
SELECT t.Name, COUNT(*) as Cnt FROM Tag t
JOIN ImageTag it ON t.Id = it.TagId
GROUP BY t.Name ORDER BY Cnt DESC LIMIT 20;

-- 查询数据库文件大小
SELECT page_count * page_size as SizeBytes FROM pragma_page_count(), pragma_page_size();
```

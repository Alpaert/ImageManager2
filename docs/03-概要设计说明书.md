# ImageManager2 — 概要设计说明书 (HLD)

## 1. 引言

### 1.1 文档目的
本文档描述 ImageManager2 的系统架构、模块划分、技术选型和关键数据流，作为详细设计的依据。

### 1.2 设计原则
- **分层架构**：表示层、领域层、基础设施层、公共层严格分层，上层依赖下层
- **接口隔离**：每个服务接口职责单一，Repository 处理持久化，Service 处理计算
- **异步优先**：所有 I/O 和 CPU 密集型操作异步执行，不阻塞 UI 线程
- **缓存分层**：内存 LRU → 磁盘文件 → 实时生成，逐级回退

## 4. 模块设计

### 4.1 数据层 (Infrastructure/Data)

**职责**：SQLite 数据库初始化、表结构管理、数据迁移、Repository 实现

```
AppDbContext

Repositories (每个方法独立创建 Connection)
├── ImageMetaRepository     # 图片 CRUD + 标签联合查询
├── TagRepository           # 标签 CRUD + 收藏 + 重命名/合并

DataMigrator
└── MigrateFromJsonAsync()  # 旧版 JSON → SQLite
```

### 4.2 哈希模块 (Infrastructure/Hashing)

**职责**：文件哈希和感知哈希计算

```
HashService : IHashService
├── ComputeFileHash()       # MD5 文件哈希
├── ComputePerceptualHash() # 组合感知哈希 (aHash|dHash|wHash|histogram)
├── HammingDistance()       # 汉明距离 (比特位差异计数)
├── CompareHistograms()     # 直方图交集 (0.0~1.0)
└── AreSimilarByMultiHash() # 三哈希投票 (2/3 通过)
```

**感知哈希流水线**：
1. 解码图片（最大 256px，利用 JPEG 分层解码）
2. 转为灰度像素数组
3. 并行计算四个哈希分量：
   - **aHash**：缩放到 8×8，比较每个像素与均值
   - **dHash**：缩放到 9×8，比较相邻像素差异
   - **wHash**：缩放到 32×32，2D Hadamard 变换，取左上 8×8 与中值比较
   - **Histogram**：缩放到 100px，4×4×4 RGB 直方图归一化
4. 拼接为 `"{aHash}|{dHash}|{wHash}|{histogram}"`

### 4.3 图像模块 (Infrastructure/Imaging)

**职责**：缩略图生成、尺寸读取、哈希输入解码

```
ThumbnailGenerator (static)
├── Generate()              # 按宽度生成 JPEG 缩略图
│   ├── SKCodec.GetScaledDimensions()  # 利用 JPEG 原生缩放
│   └── SKBitmap.Resize()              # 精确调整
├── GetDimensions()         # 读取宽高
├── DecodeForHashInput()    # 低分辨率解码 (max 256px)
├── DecodeForAnalysis()     # 按需解码
└── LoadGrayBytes()         # 灰度像素提取
```

### 4.4 缓存模块 (Infrastructure/Caching)

**职责**：缩略图二级缓存管理

```
ThumbnailCacheService : IThumbnailCacheService
├── L1: ConcurrentDictionary<string, CacheEntry>
│   ├── 50MB 上限，LRU 淘汰
│   └── ConcurrentDictionary + Interlocked 计数
├── L2: DiskThumbnailCache
│   ├── 按解码宽度分子目录 (w200/, w300/, ...)
│   ├── 文件名 = MD5(小写路径).jpg
│   └── EstimateDiskUsage()
└── GetOrCreateThumbnailAsync()
    ├── L1 命中 → 返回
    ├── L2 命中 → 提升到 L1 → 返回
    └── 未命中 → ThumbnailGenerator.Generate() → 存入 L2+L1 → 返回
```

## 5. 关键数据流

### 5.1 文件夹加载流程

```
用户选择文件夹
  → MainWindowViewModel.LoadFolderAsync()
    → ImageMetaRepository.GetByFolderIdAsync(folderId)  [DB 索引查询, < 50ms]
    → 排序(ImageSortOrder)
    → 分页: 计算总页数
    → PageManager.ShowPageAsync(0)
      → 创建 200 个 ImageViewItem 占位
      → 优先加载可见区域缩略图 (EstimateVisibleItemCount)
      → SemaphoreSlim(4) 并发调用 ThumbnailCacheService
      → PageChanged 事件 → VM 更新 Images 集合
  → SyncCurrentFolderAsync()  [后台: 磁盘枚举 vs DB 对比]
    → 新增文件: 批量 upsert
    → 删除文件: 批量删除 (同时清磁盘缓存)
  → PrecomputeHashesAsync()  [后台: Channel 生产者-消费者]
    → I/O 生产者: File.ReadAllBytes → DecodeForHashInput
    → CPU 消费者: HashService.ComputePerceptualHash
    → 批量 upsert 哈希结果
```

### 5.2 标签搜索流程

```
用户输入搜索文本 → Enter
  → TagSearchController.SearchByTagAsync(text, folderPaths)
    → ParseTagNames() 解析运算符
    → 根据运算符组合调用 ImageMetaRepository 对应方法:
      - GetFilePathsByTagsAsync()      [AND/OR]
      - GetFilePathsByTagsExcludingAsync() [AND/OR + NOT]
      - GetFilePathsByTagAndEachAsync() [AND-each]
      - GetFilePathsWithNoTagsAsync()   [-every]
    → 与当前文件夹文件列表取交集
    → SearchCompleted 事件 → VM 更新分页和 Images
    → RefreshCoTagSuggestionsAsync()
      → GetCoOccurringTagsAsync() [查询共现标签]
      → SuggestionsChanged 事件 → 更新下拉建议
```

### 5.3 相似图片搜索流程

```
用户右键 → "查找相似图片" 或拖拽图片到搜索区
  → MainWindowViewModel.SearchSimilarAsync(filePath)
    → SimilarImageService.FindSimilarAsync(basePath, candidates)
      → PreloadHashCacheAsync()  [从 DB 加载所有感知哈希: Dictionary<string,string>]
      → GetOrComputeBaseHashAsync(basePath)  [从文件重新计算基准哈希]
      → Parallel.ForEach(candidates)
        → 阶段 1: CompareHistograms(threshold=0.35) [快速过滤]
        → 阶段 2: AreSimilarByMultiHash() [三哈希投票, 2/3 通过]
      → 返回相似图片路径列表
    → 找到第一个相似图在 _allFiles 中的索引
    → 计算目标页码 = index / PageSize (200)
    → ShowPageAsync(targetPage)
    → 遍历 Images 设置 IsSelected = true (蓝色高亮)
    → StatusText = "找到 N 张相似图片"
```

### 5.4 精确去重流程

```
用户点击 "检测重复图片"
  → MainWindowViewModel.DetectDuplicatesAsync()
    → DuplicateService.DetectAndMoveDuplicatesAsync(filePaths, targetDir)
      → 遍历文件:
        - 从 DB 读取 MD5 (若已缓存)
        - 否则计算 MD5: HashService.ComputeFileHash()
        - 读取宽高: ThumbnailGenerator.GetDimensions()
      → 按 MD5 分组, 找 count > 1 的组
      → 每组保留 max(宽×高) 图片, 其余移入 targetDir
      → 更新 DB 中被移动图片的 FilePath
    → 显示结果: "发现 N 组重复, 已移动 M 张"
```

## 6. 并发控制

| 场景 | 策略 |
|------|------|
| 哈希预计算 | `Channel<Bounded>(50)` 生产者-消费者，I/O 信号量(2) + CPU 信号量(核心数) |
| 缩略图加载 | `SemaphoreSlim(4)` 限制并发解码 |
| 相似搜索 | `Parallel.ForEach` + `lock(syncRoot)` 收集结果 |
| 设置保存 | `SemaphoreSlim(1,1)` 防止并发写入 AppSetting 表 |
| 内存缓存 | `ConcurrentDictionary` + `Interlocked` 原子操作 |
| UI 线程 | 所有 I/O 和计算通过 `Task.Run` 调度到线程池 |

## 7. 错误处理

| 层次 | 策略 |
|------|------|
| 全局未处理异常 | `Program.cs` try/catch 写入桌面 `ImageManager_crash.log` |
| 文件 I/O 异常 | 跳过当前文件，记录日志，继续批量处理 |
| 数据库异常 | 事务回滚，向上抛出由调用方处理 |
| UI 操作异常 | try/catch + 状态栏显示错误信息 |
| 在线搜索异常 | HTTP 超时 30s，失败静默处理 |

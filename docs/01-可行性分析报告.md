# ImageManager2 — 可行性分析报告

## 1. 项目概述

### 1.1 项目名称
ImageManager2 — 本地图片管理与检索系统

### 1.2 项目背景
随着数字摄影、截图工具和网络下载的普及，用户本地存储的图片数量呈指数级增长。传统的文件管理器（如 Windows 资源管理器）仅提供基本的文件夹浏览和缩略图查看功能，无法满足以下需求：

- **海量图片快速浏览**：数千张图片的流畅翻页与缩放
- **标签化管理与检索**：跨文件夹的标签分类、组合搜索
- **重复与相似图片检测**：释放磁盘空间
- **在线以图搜图**：快速查找图片来源

旧版 WPF 项目（ImageManager v1）已实现基础功能，但存在架构臃肿、性能瓶颈和可维护性差等问题。ImageManager2 是基于 .NET 8 + Avalonia 的全新重构版本，目标是构建一个高性能、可扩展的跨平台桌面图片管理工具。

### 1.3 项目目标
- 提供流畅的万级图片浏览体验（分页加载、多级缓存、异步哈希计算）
- 支持标签化图片管理与组合搜索（AND/OR/NOT/AND-each 四种运算符）
- 实现精确去重（MD5）与相似图片搜索（多哈希投票 + 直方图预过滤）
- 提供三种瀑布流布局模式（网格、垂直瀑布流、水平自适应）
- 支持深色/浅色主题切换与完整快捷键系统
- 集成在线以图搜图（SauceNAO / IQDB / Trace.moe 等）
- 从旧版 WPF JSON 格式无缝数据迁移

## 2. 可行性分析

### 2.1 技术可行性

| 维度 | 评估 | 说明 |
|------|------|------|
| **UI 框架** | 可行 | Avalonia 12.0 支持 Windows/macOS/Linux，提供完整的 MVVM 绑定、编译时类型检查和 Fluent 主题 |
| **数据库** | 可行 | SQLite + Dapper 提供零配置嵌入式存储，WAL 模式支持并发读写，单文件易于备份 |
| **图像处理** | 可行 | SkiaSharp 提供跨平台 GPU 加速图像解码，支持分层 JPEG 解码避免全分辨率加载 |
| **感知哈希** | 可行 | aHash/dHash/wHash 三种算法组合 + 颜色直方图，wHash（Walsh-Hadamard）比 DCT 快 5-10 倍 |
| **.NET 8** | 可行 | 提供 AOT 编译、性能优化和跨平台支持 |
| **技术风险** | 低 | 所有依赖均为成熟开源项目，社区活跃，文档完善 |

### 2.2 操作可行性
- 用户界面采用标准 Windows 桌面应用交互模式（菜单栏、右键菜单、拖拽、快捷键）
- 标签搜索采用类搜索引擎的运算符语法，学习成本低
- 设置窗口分类清晰，提供即时预览
- 支持从旧版一键数据迁移，降低切换成本

### 2.3 经济效益
- **开发成本**：基于开源技术栈，无商业授权费用
- **硬件成本**：SQLite 嵌入式数据库无需服务器，最低 50MB 内存即可运行
- **用户收益**：去重功能可直接释放磁盘空间；标签管理提升图片检索效率

### 2.4 法律与合规
- 所有依赖项使用 MIT/Apache 2.0 等宽松开源许可证
- 在线搜图功能仅作为浏览器跳转中介，不存储第三方数据

## 3. 项目范围

### 3.1 包含功能
- 文件夹管理（添加/删除/别名/重定位）
- 图片浏览（缩略图网格/瀑布流/分页/缩放）
- 标签系统（添加/删除/重命名/合并/收藏）
- 标签搜索（a/o/e/- 运算符 + 共现标签循环 + 未标记筛选）
- 图片预览（全屏查看/缩放/导航）
- 精确去重（MD5 分组，保留最大分辨率）
- 相似图片搜索（多哈希投票，页内跳转高亮）
- 在线以图搜图（9 个搜索引擎）
- 主题系统（深色/浅色切换 + 自定义强调色）
- 壁纸功能（窗口背景图片）
- 快捷键系统（可自定义）
- 文件夹实时监控（FileSystemWatcher）
- 数据迁移（旧版 JSON → SQLite）

### 3.2 不包含功能
- 图片编辑/裁剪/滤镜
- 云端同步/备份
- 多用户协作
- 视频文件管理
- AI 自动打标（ONNX Runtime 已集成但尚未启用）
- 模糊去重（fuzzy duplicate，当前仅精确 MD5 去重）

## 4. 风险分析

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| 大文件夹性能退化 | 中 | 高 | 分页加载(200/页)、生产者-消费者哈希计算、多级缓存 |
| SQLite 并发瓶颈 | 低 | 中 | WAL 模式、SemaphoreSlim 串行化写操作 |
| Avalonia 平台兼容性 | 低 | 中 | 优先保证 Windows 体验，macOS/Linux 作为次级目标 |
| 感知哈希误判 | 低 | 低 | 三哈希投票机制(2/3 通过) + 直方图预过滤 |

## 6. 结论

基于成熟的开源技术栈（.NET 8 / Avalonia / SQLite / SkiaSharp），ImageManager2 项目在技术上完全可行。四层架构设计保证了可维护性和可测试性，多级缓存和异步计算策略解决了海量图片的性能瓶颈。项目已进入功能完善和性能优化阶段，核心功能均已实现并经过验证。

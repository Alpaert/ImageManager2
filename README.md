## 二、技术深度亮点（远超平均水准）

### 1. AI/ML 集成 —— 最大亮点

- 使用 **ONNX Runtime** 加载 **WD14 SwinV2-v3** 深度学习模型进行图片自动打标
- 模型从 HuggingFace 自动下载（含完整性校验、尺寸回退估算、进度回调）
- 完整管道：ONNX 推理（448×448 BGR NHWC）→ DeepSeek 批量翻译（50 条/批）→ 用户审核确认 → TagMapping 映射写入
- `Channel<Bounded>(50)` 生产者-消费者模式编排，I/O 与 CPU 信号量分离
- **此模块在本科毕设中极少出现**，单独写一章足够充实

### 2. 多哈希投票相似图片搜索

- 四合一组合感知哈希：aHash | dHash | wHash | 颜色直方图
- 汉明距离比较 + 2/3 多数投票机制
- 两阶段搜索：直方图预过滤（阈值 0.35）→ 多哈希投票精排
- `Parallel.ForEach` 并行化
- 不是调第三方库，而是**自主实现算法**

### 3. 并发与性能设计

- `Channel<T>` 生产者-消费者模式做 I/O 与 CPU 分离
- L1 内存 `ConcurrentDictionary`（50MB 上限 LRU 淘汰）+ L2 磁盘文件二级缩略图缓存
- `SemaphoreSlim` 控制并发，可见优先加载策略
- 标签批量加载（2 次 SQL 而非 N+1）
- SQLite WAL 模式 + 外键约束

### 4. 自定义 UI 布局

- 三种瀑布流模式（Grid / Vertical Masonry / Horizontal Justified）
- **全部手写**，继承 `Panel` 实现 `MeasureOverride` / `ArrangeOverride`
- 非第三方控件，体现对 WPF/Avalonia 布局系统的深入理解

### 5. 标签搜索 DSL

- 四种运算符：`a`（AND）、`o`（OR）、`e`（AND-each）、`-`（NOT）
- 共现标签循环状态机（无结果时自动切换到下一个共现标签）
- 前缀联想输入
- 有一定编译原理/解析器设计味道

### 6. 在线搜图集成

- SauceNAO、IQDB、trace.moe、ascii2d、Google Lens、Yandex、Baidu 等 **7 个搜索引擎**
- SauceNAO 和 trace.moe 为自动 POST 上传并解析 JSON 结果
- 右键菜单触发，支持剪贴板批量复制

## 三、架构设计评价

### 优点

| 方面 | 评价 |
|------|------|
| **分层清晰** | Common → Core → Infrastructure → App，依赖方向正确，接口与实现分离 |
| **MVVM 规范** | Views 纯 AXAML 绑定，ViewModels 通过 CommunityToolkit.Mvvm 源生成器驱动，无 View 反向引用 |
| **DI 完备** | Microsoft.Extensions.DependencyInjection，全组件通过构造函数注入 |
| **数据库设计** | 9 张表，外键约束，幂等迁移，兼容旧版 JSON→SQLite |
| **错误处理** | 全局异常日志写入 `%LocalAppData%`，ONNX/翻译均有重试机制 |

### 可改进项（答辩时可能被问到）

| 问题 | 说明 |
|------|------|
| **模糊去重未实现** | `DuplicateService` 中 fuzzy 逻辑为 TODO，论文中可标注为后续工作 |
| **瀑布流无虚拟化** | `SmartWaterfallPanel` 对所有元素全量 measure/arrange，大量图片时性能会下降 |
| **文件夹搜索未接入** | MainWindow 中有搜索栏 UI 绑定但后端无实现 |
| **部分命令为空** | `StopSearch` 等命令为 `{ }` 空实现 |

> **答辩建议**：遇到上述问题时，坦诚说明这是工程上的取舍——优先完成了核心功能（AI 打标、相似搜索、标签系统），将上述项列为已知局限和改进方向即可，导师通常能理解。
